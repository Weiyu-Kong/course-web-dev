# 第一部分：数据库设计

## 二、从需求提取实体

需求中有三个核心名词：

- Traveler：谁在使用网站和购买车票。
- Train：可以被搜索和预订的车次。
- Booking：谁预订了哪一趟车。

它们之间的关系是：

```text
Traveler 1 ───── makes ───── * Booking
Train    1 ─── associated ── * Booking
```

一个 Traveler 可以创建多个 Booking，一个 Booking 只属于一个 Traveler。

一趟 Train 可以出现在多个 Booking 中，一个 Booking 只关联一趟 Train。

因此 `Booking` 是连接 `Traveler` 与 `Train` 的关联实体。

## 三、Traveler 表

文件：`backend/database/schema.sql`

```sql
CREATE TABLE Traveler (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  name VARCHAR(100) NOT NULL,
  username VARCHAR(32) NOT NULL,
  email VARCHAR(254) NOT NULL,
  nationality VARCHAR(60) NOT NULL,
  birth_date DATE NOT NULL,
  gender ENUM('Male', 'Female') NOT NULL,
  passport_no VARCHAR(30) NOT NULL,
  passport_expiration_date DATE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uq_traveler_username (username),
  UNIQUE KEY uq_traveler_email (email),
  UNIQUE KEY uq_traveler_passport (passport_no)
);
```

讲解重点：

1. `id` 是内部主键，不使用 username 作为主键。
2. username、email 和 passport_no 具有唯一约束。
3. 数据库只保存 `password_hash`，不保存明文 password。
4. `created_at` 由数据库生成，不由浏览器决定。

## 四、Train 表

```sql
CREATE TABLE Train (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  train_number VARCHAR(12) NOT NULL,
  service_date DATE NOT NULL,
  origin VARCHAR(60) NOT NULL,
  destination VARCHAR(60) NOT NULL,
  departure_location VARCHAR(100) NOT NULL,
  departure_time TIME NOT NULL,
  arrival_location VARCHAR(100) NOT NULL,
  arrival_time TIME NOT NULL,
  duration_minutes SMALLINT UNSIGNED NOT NULL,
  is_bookable BOOLEAN NOT NULL DEFAULT TRUE,
  PRIMARY KEY (id),
  UNIQUE KEY uq_train_service (train_number, service_date),
  KEY idx_train_search (
    origin,
    destination,
    service_date,
    is_bookable
  )
);
```

PPT 中 Train 的字段可以直接对应到 SQL：

| ER 图字段 | SQL 字段 |
| --- | --- |
| train number | `train_number` |
| service date | `service_date` |
| origin | `origin` |
| destination | `destination` |
| departure location | `departure_location` |
| departure time | `departure_time` |
| arrival location | `arrival_location` |
| arrival time | `arrival_time` |

`UNIQUE(train_number, service_date)` 表示同一服务日期不能重复创建同一个车次。

## 五、Booking 表

```sql
CREATE TABLE Booking (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  booking_no VARCHAR(24) NOT NULL,
  passenger_id BIGINT UNSIGNED NOT NULL,
  train_id BIGINT UNSIGNED NOT NULL,
  ticket_class ENUM(
    'standing ticket',
    'Second Class',
    'First Class',
    'Business Class'
  ) NOT NULL,
  ticket_type ENUM('Adult', 'Child', 'Student') NOT NULL,
  passenger_name VARCHAR(100) NOT NULL,
  passenger_id_no VARCHAR(30) NOT NULL,
  passenger_nationality VARCHAR(60) NOT NULL,
  idempotency_key CHAR(36) NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uq_booking_no (booking_no),
  FOREIGN KEY (passenger_id) REFERENCES Traveler(id),
  FOREIGN KEY (train_id) REFERENCES Train(id)
);
```

其中：

- `passenger_id` 实现 Traveler 1 → * Booking。
- `train_id` 实现 Train 1 → * Booking。
- passenger name、ID 和 nationality 是下单时的快照。
- `idempotency_key` 防止重复点击 Confirm 创建两条订单。

## 六、TravelerSession 为什么不在核心 ER 图中

登录还需要 `TravelerSession` 表，但它是认证基础设施，不是购票业务的核心实体：

```sql
CREATE TABLE TravelerSession (
  token_hash CHAR(64) PRIMARY KEY,
  traveler_id BIGINT UNSIGNED NOT NULL,
  expires_at DATETIME NOT NULL,
  FOREIGN KEY (traveler_id)
    REFERENCES Traveler(id)
    ON DELETE CASCADE

```

课堂上先画 Traveler、Train、Booking，再说明实际应用还会增加支撑表。

# 第二部分：DB Connection 与 DB Access

## 八、DB Connection 是什么

PPT 定义：Database connection 是 Web Server 向 DBMS 发送 SQL，并接收结果的通信通道。

文件：`backend/db.js`

```js
const mysql = require('mysql2/promise');

const db = mysql.createPool({
  host: process.env.DB_HOST || '127.0.0.1',
  port: Number(process.env.DB_PORT || 3306),
  user: process.env.DB_USER || 'root',
  password: process.env.DB_PASSWORD || '',
  database: process.env.DB_NAME || 'railway_demo',
  waitForConnections: true,
  connectionLimit: 10,
  dateStrings: true,
});

module.exports = db;
```

逐项解释：

- `mysql2/promise` 支持 async/await。
- `createPool()` 创建连接池。
- host、user、password、database 说明连接目标。
- `connectionLimit` 限制同时打开的连接。
- `module.exports` 让其他文件共享这个连接池。

配置放在 `.env`：

```dotenv
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=change-me
DB_NAME=railway_demo
```

密码不能直接写进提交到 Git 的 JavaScript 文件。

## 九、DB Access 是什么

DB Connection 只是通道；DB Access 函数负责具体 SQL 操作。

文件：`backend/db-access.js`

```js
const db = require('./db');

async function findTrains(origin, destination, date) {
  const [rows] = await db.execute(
    `SELECT * FROM Train
     WHERE LOWER(origin) = LOWER(?)
       AND LOWER(destination) = LOWER(?)
       AND service_date = ?
       AND is_bookable = TRUE
     ORDER BY departure_time`,
    [origin, destination, date],
  );

  return rows.map(mapTrain);
}
```

对应 PPT 中的核心形态：

```text
findTrains(origin, destination, date)
  → db.execute(SQL, parameters)
  → return rows
```

### 为什么使用问号

```sql
WHERE origin = ?
  AND destination = ?
  AND service_date = ?
```

实际值单独放入数组：

```js
[origin, destination, date]
```

这是参数化查询。不要把用户输入直接拼进 SQL 字符串。

### 为什么做字段映射

```js
function mapTrain(row) {
  return {
    id: Number(row.id),
    trainNumber: row.train_number,
    serviceDate: row.service_date,
    origin: row.origin,
    destination: row.destination,
    departureLocation: row.departure_location,
    departureTime: String(row.departure_time).slice(0, 5),
    arrivalLocation: row.arrival_location,
    arrivalTime: String(row.arrival_time).slice(0, 5),
    durationMinutes: Number(row.duration_minutes),
  };
}
```

数据库使用 snake_case，JavaScript API 使用 camelCase。映射函数把数据库格式隔离在 DB Access 层。

## 十、DB Access 课堂练习

让学生独立实现：

```js
async function findTrainById(id) {
  const [rows] = await db.execute(
    'SELECT * FROM Train WHERE id = ?',
    [id],
  );

  return rows[0];
}
```

提问：

1. 为什么结果要写成 `[rows]`？
2. `findTrains()` 返回数组，`findTrainById()` 应返回什么？
3. 如果查询不到，应该由 DB Access 还是 Controller 返回 HTTP 404？

答案：HTTP 404 属于 Web/Controller 概念，DB Access 只返回 `null` 或空数组。

# 第三部分：Web Server

## 十一、Route → Controller → DB Access

PPT 中的结构：

```text
app.get('/api/trains', searchTrains)
                  ↓
       searchTrains(req, res)
                  ↓
 findTrains(origin, destination, date)
                  ↓
              MySQL
```

每层只回答一个问题：

- Route：哪个 HTTP 请求由哪个函数处理？
- Controller：收到请求后执行哪些步骤？
- DB Access：执行哪条 SQL？
- DB Connection：如何连接 DBMS？

## 十二、Route 写法

文件：`backend/server.js`

```js
const express = require('express');
const { searchTrains } = require('./controllers');

const app = express();

app.get('/api/trains', searchTrains);
```

这一行就是 RESTful Route：

```text
HTTP method: GET
Resource URL: /api/trains
Controller: searchTrains
```

其他资源：

```js
app.get('/api/trains/:id', getTrain);
app.post('/api/travelers', registerTraveler);
app.post('/api/sessions', loginTraveler);
app.delete('/api/session', logoutTraveler);
app.post('/api/bookings', requireTraveler, createBooking);
app.get('/api/bookings/:number', requireTraveler, getBooking);
```

## 十三、Controller 写法

文件：`backend/controllers.js`

```js
async function searchTrains(req, res, next) {
  try {
    // 1. Read parameters from the request.
    const criteria = validateSearch(req.query);

    // 2. Ask DB Access for matching trains.
    const trains = await findTrains(
      criteria.origin,
      criteria.destination,
      criteria.date,
    );

    // 3. Return a JSON response.
    res.json({
      criteria,
      count: trains.length,
      trains,
    });
  } catch (error) {
    next(error);
  }
}
```

为了对应 PPT，也可以先展示最小版本：

```js
async function searchTrains(req, res) {
  const { origin, destination, date } = req.query;

  const trains = await findTrains(
    origin,
    destination,
    date,
  );

  res.json(trains);
}
```

然后逐步加入 validation、统一错误处理和 result count。

## 十四、按四步阅读 Controller

### 1. Read parameters

```js
const { origin, destination, date } = req.query;
```

访问示例：

```text
/api/trains?origin=Shanghai&destination=Beijing&date=2026-05-31
```

### 2. Validate parameters

```js
if (!origin || !destination || !date) {
  return res.status(400).json({
    error: 'Missing search criteria',
  });
}
```

完整项目把它提取为：

```js
const criteria = validateSearch(req.query);
```

这样注册、登录和 Booking 也能使用各自的校验函数。

### 3. Query the database

```js
const trains = await findTrains(
  origin,
  destination,
  date,
);
```

Controller 不写 SQL，只调用描述业务含义的函数。

### 4. Return response

```js
res.json(trains);
```

或返回带元数据的对象：

```js
res.json({ criteria, count: trains.length, trains });
```

# 第四部分：RESTful API

## 十五、资源与 HTTP Method

RESTful API 把系统操作映射到资源和 HTTP 方法：

```text
GET     /api/trains          search/read trains
POST    /api/bookings        create a booking
GET     /api/bookings/:no    read a booking
POST    /api/travelers       create a traveler
POST    /api/sessions        create a login session
DELETE  /api/session         delete current session
```

如果课程后续加入订单修改和删除，可以扩展：

```text
PUT     /api/bookings/:id    update a booking
DELETE  /api/bookings/:id    delete a booking
```

当前需求没有取消和修改订单，因此项目没有实现这两个 endpoint。

## 十六、三种调用 API 的方式

### Browser

```text
http://localhost:3000/api/trains?origin=Shanghai&destination=Beijing&date=2026-05-31
```

### Bash

```bash
curl "http://localhost:3000/api/trains?origin=Shanghai&destination=Beijing&date=2026-05-31"
```

### JavaScript

```js
fetch('/api/trains?origin=Shanghai&destination=Beijing&date=2026-05-31')
  .then((response) => response.json())
  .then((data) => console.log(data));
```

课堂建议：先用 Browser 验证 GET，再用 curl 强调 API 与网页无关，最后接到前端。

## 十七、REST API 与页面 URL 的区别

```text
/index.html                 → HTML document
/register.html              → HTML document
/api/trains                 → JSON resource
/api/bookings/RB1234        → JSON resource
```

网页是给人看的，API 是给程序调用的。

# 第七部分：用相同结构完成 Traveler 注册

## 二十一、Route

```js
app.post('/api/travelers', registerTraveler);
```

使用复数名词 `/travelers` 表示 Traveler 资源集合，POST 表示创建新资源。

## 二十二、Controller

```js
async function registerTraveler(req, res, next) {
  try {
    // 1. Validate request body.
    const traveler = validateRegistration(req.body);

    // 2. Hash the password.
    traveler.passwordHash = await hashPassword(
      traveler.password,
    );

    // 3. Insert the Traveler through DB Access.
    const created = await createTraveler(traveler);

    // 4. Create login session and return JSON.
    await startSession(res, created.id);
    res.status(201).json({
      user: publicTraveler(created),
    });
  } catch (error) {
    next(error);
  }
}
```

## 二十三、DB Access

```js
async function createTraveler(traveler) {
  const [result] = await db.execute(
    `INSERT INTO Traveler
     (name, username, email, nationality,
      birth_date, gender, passport_no,
      passport_expiration_date, password_hash)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)`,
    [
      traveler.name,
      traveler.username,
      traveler.email,
      traveler.nationality,
      traveler.dateOfBirth,
      traveler.gender,
      traveler.passportNumber,
      traveler.passportExpirationDate,
      traveler.passwordHash,
    ],
  );

  return { id: result.insertId, ...traveler };
}
```

## 二十四、Frontend

`frontend/js/register.js`：

```js
const formData = new FormData(form);
const traveler = Object.fromEntries(formData);
traveler.acceptTerms = formData.has('acceptTerms');

await api('/api/travelers', {
  method: 'POST',
  body: JSON.stringify(traveler),
});
```

### 注册完整路径

```text
POST /api/travelers
→ registerTraveler()
→ validateRegistration()
→ hashPassword()
→ createTraveler()
→ INSERT INTO Traveler
→ createSession()
→ 201 Created + Set-Cookie
```

async function createBooking(req, res, next) {

# 第九部分：Validation

## 二十七、三层校验

```text
Frontend validation  → 立即帮助用户修正
Controller validation → 不信任任何外部请求
Database constraint   → 保证最终数据一致性
```

搜索 Controller 的基础校验：

```js
if (!origin || !destination || !date) {
  return res.status(400).json({
    error: 'Missing search criteria',
  });
}
```

项目提取为：

```js
const criteria = validateSearch(req.query);
```

注册的数据库约束：

```sql
UNIQUE KEY uq_traveler_username (username),
UNIQUE KEY uq_traveler_email (email),
UNIQUE KEY uq_traveler_passport (passport_no)
```

即使两个请求同时提交相同 username，数据库也只允许一个成功。

# 十一、课堂检查题

1. DB Connection 与 DB Access 有什么区别？
2. Route 与 Controller 有什么区别？
3. SQL 为什么不直接写在 Route 中？
4. 为什么 `findTrains()` 不接收 `req` 和 `res`？
5. `req.query`、`req.params`、`req.body` 分别来自哪里？
6. GET `/api/trains` 为什么使用 query string？
7. POST `/api/travelers` 为什么使用 JSON body？
8. 为什么浏览器不能直接连接 MySQL？
9. 为什么 SQL 中使用 `?`？
10. 为什么前端校验不能代替后端校验？

参考总结：

```text
Route decides WHO handles the request.
Controller decides WHAT the request should do.
DB Access decides WHICH SQL should run.
DB Connection decides HOW to communicate with MySQL.
```

学生能准确说出这四句话，并能顺着 `GET /api/trains` 找到每一层代码，就完成了本阶段的学习目标。
