# Railway 12306 全栈课程教案

技术栈：MySQL、Node.js、Express、RESTful API、HTML、CSS、JavaScript  
案例：车次搜索、注册、登录和订票  

---

##  总体流程

```text
运行服务器
  ↓
写第一个后端并读取数据库
  ↓
增加一个带查询条件的新后端
  ↓
理解 HTML、CSS、JavaScript 的分工
  ↓
分四步完成前端并连接 API
  ↓
按相同方法独立完成注册功能
```

课程采用“先做出来，再解释，再扩展”的节奏。学生每完成一小步，都能立即在终端或浏览器中看到结果。

### 课程最终目标

学生能够解释并独立实现：

```text
Browser → HTTP Request → Express → SQL → MySQL
Browser ← JSON Response ← Express ← Query Result ← MySQL
```

### 项目文件只保留三层

```text
Database    backend/database/schema.sql + seed.sql
Backend     backend/db.js + validation.js + server.js
Frontend    frontend/*.html + css/style.css + js/*.js
```

这比工程项目常见的 controller/service/repository 分层更适合第一次全栈课。等学生能完整说出一次请求经过哪些代码后，再引入复杂分层。

# PPT 1 — Get your hands dirty: run your server

1. install and run the first server
2. modify the webpages to see the updated content

## 二、本页教学目标

学生只需要理解三件事：

- Node.js 可以执行 JavaScript 文件。
- Express 可以启动 HTTP 服务器。
- 浏览器访问服务器，服务器把 HTML 文件返回给浏览器。

本阶段不要讲数据库、REST、Cookie 或复杂架构。

## 三、Step 1：安装并运行第一台服务器

### 1. 创建 package.json

展示项目中的核心依赖：

```json
{
  "scripts": {
    "start": "node backend/server.js",
    "dev": "node --watch backend/server.js"
  },
  "dependencies": {
    "dotenv": "^16.4.7",
    "express": "^4.21.2",
    "mysql2": "^3.11.5"
  }
}
```

执行：

```bash
npm install
```

解释：`npm install` 根据 `package.json` 下载项目依赖，生成 `node_modules`。它不是启动服务器的命令。

### 2. 先写最小服务器

教师可以先把 `backend/server.js` 临时简化成：

```js
const express = require('express');

const app = express();
const port = 3000;

app.get('/', (req, res) => {
  res.send('<h1>Hello, Railway!</h1>');
});

app.listen(port, () => {
  console.log(`Server: http://127.0.0.1:${port}`);
});
```

运行：

```bash
npm start
```

浏览器打开：

```text
http://127.0.0.1:3000
```

### 3. 逐行讲解

```js
const express = require('express');
```

从已安装的依赖中载入 Express。

```js
const app = express();
```

创建一个 Web 应用。后面所有 URL 都注册在 `app` 上。

```js
app.get('/', (req, res) => { ... });
```

- `get` 是 HTTP GET 方法。
- `'/'` 是主页 URL。
- `req` 表示浏览器请求。
- `res` 用来返回响应。

```js
app.listen(3000);
```

让进程监听 3000 端口。服务器会持续运行，直到按 `Ctrl+C`。

## 四、Step 2：修改网页并看到更新

### 1. 从 res.send 过渡到 HTML 文件

创建 `frontend/index.html`：

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Railway 12306</title>
</head>
<body>
  <h1>Find your next train.</h1>
  <p>This is our first webpage.</p>
```

把服务器改为：

```js
const path = require('node:path');

const app = express();
const frontendPath = path.join(__dirname, '../frontend');

app.listen(3000, () => {
  console.log('Server: http://127.0.0.1:3000');

```

`express.static()` 会把 `frontend` 目录中的 HTML、CSS 和 JavaScript 文件作为静态资源提供给浏览器。

### 2. 做一次可见修改

把：

```html
<p>This is our first webpage.</p>
```

改为：

```html

```

## 六、本页常见错误

- `Cannot find module 'express'`：没有执行 `npm install`。
- `EADDRINUSE`：3000 端口已被另一个进程占用。
- 页面没有变化：浏览器缓存或修改了错误文件。
- 从文件管理器直接双击 HTML：此时地址是 `file://`，没有经过 Express。

## 十、Step 1：写后端代码

### 1. 连接数据库

文件：`backend/db.js`

```js
const mysql = require('mysql2/promise');

const pool = mysql.createPool({
  host: process.env.DB_HOST || '127.0.0.1',
  port: Number(process.env.DB_PORT || 3306),
  user: process.env.DB_USER || 'root',
  password: process.env.DB_PASSWORD || '',
  database: process.env.DB_NAME || 'railway_demo',
  connectionLimit: 10,
});

module.exports = pool;
```

为什么使用连接池：请求结束后连接可被下一个请求复用，不需要每次重新连接 MySQL。

### 2. 服务器载入 db

在 `backend/server.js` 顶部：

```js
require('dotenv').config();
const db = require('./db');
```

`dotenv` 读取 `.env`，`db` 是共享连接池。

## 十一、Step 2：读取已创建数据库中的数据

先写一个最简单的接口：

```js
app.get('/api/trains', async (req, res) => {
  const [rows] = await db.execute(
    'SELECT * FROM trains ORDER BY departure_time',
  );

  res.json(rows);
});
```

浏览器打开：

```text
http://127.0.0.1:3000/api/trains
```

应看到 JSON 数组。

### 解释 async/await

数据库查询需要时间，Node.js 不应该阻塞整个服务器。

```js
const [rows] = await db.execute(...);
```

`await` 表示当前函数等待查询结果，但 Node.js 仍能处理其他事件。使用 `await` 的函数必须加 `async`。

## 十二、Step 3：返回数据并显示在网页

### 1. HTML 增加容器

```html
<button id="load-trains">Load trains</button>
<section id="results"></section>
```

### 2. JavaScript 请求 API

```js
document.querySelector('#load-trains').addEventListener('click', async () => {
  const response = await fetch('/api/trains');
  const trains = await response.json();

  document.querySelector('#results').innerHTML = trains
    .map((train) => `
      <article>
        <h2>${train.train_number}</h2>
        <p>${train.origin_city} → ${train.destination_city}</p>
      </article>

    .join('');

```

### 3. 分清两种 JavaScript

- `backend/server.js` 在 Node.js 中执行，可以连接数据库。
- `frontend/js/home.js` 在浏览器中执行，可以操作页面。
- 两者通过 HTTP 和 JSON 通信。

浏览器绝不能直接知道数据库密码或直接连接 MySQL。

# PPT 3 — Get your hands dirty: build a new backend

1. write backend code with a new query
2. access the data in the created db
3. return the data and show it on the webpage

## 十五、本页教学目标

把无条件查询升级为带条件的 REST API：

```text
GET /api/trains?from=Shanghai&to=Beijing&date=Sun%2C+May+31
```

## 十六、Step 1：写一个新查询

最终代码位于 `backend/server.js`：

```js
app.get('/api/trains', async (req, res, next) => {
  try {
    const criteria = validateSearch(req.query);

    const [rows] = await db.execute(
      `SELECT * FROM trains
       WHERE LOWER(origin_city) = LOWER(?)
         AND LOWER(destination_city) = LOWER(?)
         AND LOWER(display_date) = LOWER(?)
         AND is_bookable = TRUE
       ORDER BY departure_time`,
      [criteria.from, criteria.to, criteria.date],
    );

    const trains = rows.map(mapTrain);
    res.json({ criteria, count: trains.length, trains });
  } catch (error) {
    next(error);
  }
});
```

### 1. 从 URL 获取查询参数

如果 URL 是：

```text
/api/trains?from=Shanghai&to=Beijing&date=Sun%2C+May+31
```

那么 Express 中：

```js
req.query.from // "Shanghai"
req.query.to   // "Beijing"
req.query.date // "Sun, May 31"
```

### 2. 参数化 SQL

SQL 使用 `?`：

```sql
WHERE origin_city = ? AND destination_city = ?
```

值放在单独数组中：

```js
[criteria.from, criteria.to, criteria.date]
```

不要写：

```js
// Wrong: user input is pasted directly into SQL.
`SELECT * FROM trains WHERE origin_city = '${req.query.from}'`
```

参数化查询既处理引号，也避免 SQL 注入。

## 十七、Step 2：访问数据库并整理字段

数据库使用 snake_case，前端使用 camelCase。服务器增加映射函数：

```js
function mapTrain(row) {
  return {
    id: Number(row.id),
    trainNumber: row.train_number,
    originCity: row.origin_city,
    destinationCity: row.destination_city,
    departureStation: row.departure_station,
    arrivalStation: row.arrival_station,
    displayDate: row.display_date,
    departureTime: String(row.departure_time).slice(0, 5),
    arrivalTime: String(row.arrival_time).slice(0, 5),
    durationMinutes: Number(row.duration_minutes),
  };
}
```

让学生观察：数据库结构和 API 结构可以不同。API 是前后端约定，不必暴露原始表结构。

## 十八、Step 3：前端发送条件并显示结果

`frontend/js/home.js`：

```js
async function searchTrains(event) {
  event.preventDefault();

  const form = event.currentTarget;
  const criteria = Object.fromEntries(new FormData(form));
  const query = new URLSearchParams(criteria);
  const data = await api(`/api/trains?${query}`);

  results.innerHTML = data.trains
    .map(trainCard)
    .join('');
}
```

为什么使用 `URLSearchParams`：它会把空格、逗号等字符正确编码，不必手工拼接 URL。

### 新增按 ID 查询一个车次

点击 Book 后进入：



```js
app.get('/api/trains/:id', async (req, res) => {
```

这是 PPT 中“build a new backend”的第二个自然示例：复用数据库连接和映射函数，只更换 URL 与 SQL。

## 二十七、Step 4：连接刚刚完成的 RESTful API

### 1. 公共 API helper

文件：`frontend/js/common.js`

```js
export async function api(path, options = {}) {
  const response = await fetch(path, {
    headers: { 'Content-Type': 'application/json' },
    ...options,
  });

  if (response.status === 204) return null;

  const data = await response.json();

  if (!response.ok) {
    throw new Error(data.error?.message || 'Request failed.');
  }

  return data;
}
```

所有页面复用同样的成功和失败规则。

### 2. 替换假数据

```js
import { api } from './common.js';

async function searchTrains(event) {
  event.preventDefault();

  const criteria = Object.fromEntries(
    new FormData(event.currentTarget),
  );

  const query = new URLSearchParams(criteria);
  const data = await api(`/api/trains?${query}`);

  renderTrains(data.trains);
}
```

### 3. 渲染结果

```js
function renderTrains(trains) {
  results.innerHTML = trains.map((train) => `
    <article class="train-card">
      <strong>${train.trainNumber}</strong>
      <p>${train.departureTime} ${train.departureStation}</p>
      <p>${train.arrivalTime} ${train.arrivalStation}</p>
      <a href="/booking.html?trainId=${train.id}">
        Book
      </a>
    </article>
  `).join('');
}
```

实际项目还使用 `escapeHtml()` 转义动态文本，避免数据被当成 HTML 执行。

## 三十一、Step 1：Add tables

### users 表

```sql
CREATE TABLE users (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  nationality VARCHAR(60) NOT NULL,
  full_name VARCHAR(100) NOT NULL,
  passport_number VARCHAR(30) NOT NULL UNIQUE,
  passport_expiration_date DATE NOT NULL,
  date_of_birth DATE NOT NULL,
  gender ENUM('Male', 'Female') NOT NULL,
  username VARCHAR(32) NOT NULL UNIQUE,
  email VARCHAR(254) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

提问：

- 为什么存 `password_hash`，不存 password？
- 为什么 username 和 email 要 UNIQUE？
- 为什么数据库约束不能只靠前端检查？

### sessions 表

```sql
CREATE TABLE sessions (
  token_hash CHAR(64) PRIMARY KEY,
  user_id BIGINT UNSIGNED NOT NULL,
  expires_at DATETIME NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

解释：Cookie 保存随机 token，数据库保存 token 的 SHA-256 hash。刷新页面后，浏览器再次携带 Cookie，服务器就能找到用户。

### 2. 注册 API

```js
app.post('/api/register', async (req, res, next) => {
  try {
    const data = validateRegistration(req.body);

        data.dateOfBirth,
        data.gender,
        data.username,
        data.email,
        passwordHash,
      ],
    );

    await createSession(res, result.insertId);

    res.status(201).json({
      user: {
        id: result.insertId,
        username: data.username,
        email: data.email,
      },
    });
  } catch (error) {
    next(error);
  }
});
```

### 3. 密码哈希

```js
async function hashPassword(password) {
  const salt = crypto.randomBytes(16).toString('hex');
  const key = await scrypt(password, salt, 64);
  return `scrypt:${salt}:${key.toString('hex')}`;
}
```

- 密码不能明文存储。
- Salt 让相同密码产生不同结果。
- scrypt 是专门面向密码的慢哈希。

### 4. 创建登录会话

```js
async function createSession(res, userId) {
  const token = crypto.randomBytes(32).toString('hex');

  await db.execute(
    `INSERT INTO sessions
     (token_hash, user_id, expires_at)
     VALUES (?, ?, ?)`,
    [tokenHash(token), userId, expiresAt],
  );

  res.setHeader(
    'Set-Cookie',
    `rail_session=${token}; Path=/; HttpOnly; SameSite=Lax`,
  );
}
```

`HttpOnly` 表示浏览器 JavaScript 无法读取 token。前端无需也不应该把它复制进 localStorage。

## 三十四、Step 4：Validation

PPT 把 validation 放在最后，非常适合教学：先完成 happy path，再逐个破坏输入并补规则。

### 前端校验负责体验

项目订票页使用简单函数立即显示错误：

```js
function validatePassenger(data) {
  if (!data.passengerName?.trim()) {
    return 'Passenger name is required.';
  }
  if (data.passengerName.trim().length < 2) {
    return 'Passenger name must contain at least 2 characters.';
  }
  if (!data.acceptTerms) {
    return 'You must accept the Terms of service.';
  }
  return '';
}
```

### 后端校验负责安全和数据正确性

文件：`backend/validation.js`

```js
function validateRegistration(input) {
  const data = {
    username: text(input.username),
    email: text(input.email).toLowerCase(),
    password: typeof input.password === 'string'
      ? input.password
      : '',
    confirmPassword: typeof input.confirmPassword === 'string'
      ? input.confirmPassword
      : '',
    acceptTerms: input.acceptTerms === true,
  };

  if (!/^[A-Za-z0-9_-]{3,32}$/.test(data.username)) {
    throw new HttpError(400, 'Invalid username.');
  }

  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(data.email)) {
    throw new HttpError(400, 'Enter a valid email address.');
  }

  if (data.password !== data.confirmPassword) {
    throw new HttpError(400, 'Passwords do not match.');
  }

  if (!data.acceptTerms) {
    throw new HttpError(400, 'You must accept the Terms of service.');
  }

  return data;
}
```

强调：用户可以绕过页面，用脚本直接调用 API，因此前端校验永远不能代替后端校验。

### 数据库校验负责最终约束

```sql
UNIQUE KEY uq_users_username (username),
UNIQUE KEY uq_users_email (email)
```

即使两个请求同时注册相同用户名，数据库仍会拒绝其中一个。

### 三层校验总结

```text
Frontend validation  → 快速反馈
Backend validation   → 不信任外部输入
Database constraints → 最终一致性
```

# 教师最后总结

让学生合上代码，用自己的语言补全：

```text
用户填写表单
→ JavaScript 使用 ______ 读取数据
→ 使用 ______ 向后端发请求
→ Express 从 ______ / ______ 读取输入
→ 使用带有 ______ 的 SQL 查询 MySQL
→ 后端用 ______ 返回数据
→ JavaScript 修改 ______ 显示结果
```

参考答案：

```text
FormData
fetch
req.query / req.body
参数占位符 ?
res.json
DOM
```

结课时学生应记住的不是某个框架 API，而是可重复使用的开发顺序：

```text
先让服务器运行
→ 再让后端拿到数据
→ 再让前端显示数据
→ 最后补齐校验与错误处理
```

以后无论做博客、课程系统、商城还是管理后台，都可以沿同一条路径开始。
